# 医疗档案与单据接口说明

本文档与 `mobile/lib/features/medical_hub/data/medical_hub_api.dart` 及详情/档案页面联调约定对齐，供后端实现与验收使用。

## 通用约定

| 项 | 说明 |
|----|------|
| Base URL | 与移动端 `AppConfig.apiBase` 一致。 |
| 鉴权 | 已登录时请求头：`Authorization: Bearer <token>`。 |
| Content-Type | JSON 接口为 `application/json`；上传识别为 `multipart/form-data`。 |
| 统一响应 | `code` 为 **int**，**`code == 0` 表示成功**；`message` 为字符串；`data` 按接口而定。 |

子女端操作他人档案时，查询参数或请求体需带 **`elderProfileId`**（与绑定老人 ID 一致）。

| form | file | 图片文件 |

### 病情文件夹

详见 **[医疗档案文件夹与单据接口文档.md](./医疗档案文件夹与单据接口文档.md)** 第 3 节。

- **GET** `/v1/medical/folders` — 列表  
- **POST** `/v1/medical/folders` — 新建（前端已对接）

### 单据列表

**GET** `/v1/medical/documents`

| Query | 说明 |
|-------|------|
| elderProfileId | 子女端必填 |
| folderId | 可选；传入时仅返回该文件夹内单据 |
| docCategory | 可选筛选 |

### 单据详情

**GET** `/v1/medical/documents/{id}`

| Query | 说明 |
|-------|------|
| elderProfileId | 子女端建议携带 |

**成功时 `data` 建议字段（camelCase）：**

| 字段 | 类型 | 前端用途 |
|------|------|----------|
| id | int | |
| elderProfileId | int | |
| title | string | 展示与编辑 |
| docCategory | string | 展示与编辑 |
| fullText | string | 结构化展示与编辑 |
| routedSpecializedApi | string | 详情摘要 |
| createdAt | string (ISO-8601) | |
| extractedFields | object | 结构化展示「抽取字段」 |
| displayBlocks | array | **优先渲染** 有序展示块，见下文 |
| structuredFields | object | 中文键 → 字符串值；无 displayBlocks 时展平为表格 |
| structuredError | string | 结构化失败原因；非空时前端展示提示条 |
| structuredRouteSource | string | `keyword_text` / `doc_classify` 等 |
| ocr | object | 含 specializedRaw、structuredError 等 |

**`displayBlocks` 项结构：**

| type | 字段 | 说明 |
|------|------|------|
| title | text | 医院名、单据标题 |
| kv | label, value | 字段名与内容 |
| table | headers, rows, caption? | **检验结果表**；rows 为二维字符串数组 |
| note / paragraph | text | 长文本 |

示例见 `docs/医疗单据结构化-后端优化Prompt.md`；**检验表专章**见 `docs/检验表结构化-后端优化Prompt.md`。

**`extractedFields` 示例：**

```json
{
  "docCategory": "PRESCRIPTION",
  "detectedDateTexts": ["2026-05-17"],
  "normalizedDates": ["2026-05-17"],
  "matchedKeywords": ["检验", "申请单"]
}
```

**`ocr` 子对象（与识别结果一致即可）：**

```json
{
  "fullText": "……",
  "routedSpecializedApi": "medical_prescription",
  "specializedRaw": { },
  "documentClasses": [ ],
  "structuredRouteSource": "keyword_text"
}
```

### 单据原件图片

**GET** `/v1/medical/documents/{id}/file`

响应：`image/*` 二进制流。

## 新增 / 扩展约定（本次前端已对接）

### 1. 编辑单据（扩展 PATCH）

**PATCH** `/v1/medical/documents/{id}`

| Query | 说明 |
|-------|------|
| elderProfileId | 子女端建议携带 |

**Request Body（字段均可选，至少传一项）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| title | string | 列表标题 |
| fullText | string | 用户修正后的 OCR 全文 |
| docCategory | string | `LAB_REPORT` / `PRESCRIPTION` / `BILLING` / `RECORD` / `OTHER` 等 |
| folderId | long / null | 归入文件夹；传 `null` 表示移出文件夹（前端 `PATCH` 带 `"folderId": null`） |

列表项建议返回 `folderId`、`folderName`，便于档案页展示归档状态。

**请求示例：**

```json
{
  "title": "门诊检验申请单",
  "fullText": "北京大学人民医院\n门诊检验申请单\n……",
  "docCategory": "LAB_REPORT"
}
```

**成功时 `data`：** 建议返回更新后的单据对象（至少含 `id`、`title`、`fullText`、`docCategory`），便于前端刷新详情。

**失败：** `code != 0`，`message` 可读（如「无权限」「单据不存在」）。

**权限：** 仅能修改当前用户有权的老人档案下单据。

---

### 2. 删除单据（新增）

**DELETE** `/v1/medical/documents/{id}`

| Query | 说明 |
|-------|------|
| elderProfileId | 子女端建议携带 |

**成功：** `code == 0`，`data` 可为 `null`。

**失败：** 单据不存在、无权限、已被引用（如日历事件关联）等需在 `message` 说明。

**副作用（建议）：** 同步删除或软删除关联存储的原图文件；若 `sourceDocumentId` 指向该单据的日历事件，可保留事件但清空关联，或一并提示用户——由产品决定，需在 `message` 中写清。

## 前端行为说明

| 功能 | 页面 | 接口 |
|------|------|------|
| 选图旋转 90° | `MedicalImagePreviewPage` | 仅本地，上传前处理 |
| 结构化全文 | `MedicalDocumentDetailPage` | 读详情 `fullText` / `ocr` / `extractedFields` |
| 编辑标题/类别/全文 | 同上 | `PATCH /v1/medical/documents/{id}` |
| 新建文件夹 | `MedicalArchivePage` | `POST /v1/medical/folders` |
| 归档至文件夹 | `MedicalArchivePage` | `PATCH /v1/medical/documents/{id}`（`folderId`） |
| 删除档案 | `MedicalArchivePage` | `DELETE /v1/medical/documents/{id}` |

### 结构化展示说明

前端**不依赖**后端额外字段即可展示：对 `fullText` 按行解析为标题行、键值对（含 `：`/`:`）、段落。

若存在 `ocr.specializedRaw`，额外展平一层 JSON 为「结构化识别（摘要）」列表。

若存在 `extractedFields`，展示「抽取字段」卡片。
