# 子女端 · 锻炼提醒接口说明

本文档与 `mobile/lib/features/child/presentation/pages/child_exercise_reminder_page.dart` 及 `ApiResponse` 约定严格对齐，供后端实现与联调使用。

## 通用约定

| 项 | 说明 |
|----|------|
| Base URL | 与移动端 `AppConfig.apiBase` 一致；下列为相对 Base 的路径。 |
| 鉴权 | 已登录时请求头携带 `Authorization: Bearer <token>`。 |
| Content-Type | `application/json` |
| 统一响应 | 与 `ApiResponse` 一致：`code` 为 **int**，**`code == 0` 表示成功**；`message` 为字符串；`data` 按接口而定。 |

成功示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": null
}
```

失败时：`code != 0`，`message` 为可读错误文案。

---

## 1. 列表（按老人档案）

**GET** `/v1/child/exercise-reminders`

### Query

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| elderProfileId | long / int | 是 | 老人档案 ID，与子女端绑定老人 `BoundElder.id` 一致 |

### 成功时 `data`

JSON **数组**。若非数组，前端会当作空列表处理。

列表项字段（**camelCase 优先；snake_case 兼容**）：

| 字段 | 前端使用 | 说明 |
|------|----------|------|
| id | 是 | 修改、删除路径用 |
| elderProfileId / elder_profile_id | 是 | |
| title | 是 | |
| exerciseType / exercise_type | 是 | |
| startTime / start_time | 是 | 建议 `HH:mm:ss`，如 `08:00:00` |
| endTime / end_time | 是 | 同上 |
| repeatRule / repeat_rule | 是 | `none` \| `daily` \| `weekly` |
| status | 是 | 如 `pending`、`completed`、`timeout`、`cancelled`、`self_confirmed`、`sensor_verified`、`missed` |
| goalValue / goal_value、goalUnit / goal_unit、intervalMinutes / interval_minutes | 否 | 前端界面不展示，解析层可接收；可省略 |

示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": [
    {
      "id": 1,
      "elderProfileId": 1,
      "title": "散步锻炼",
      "exerciseType": "散步",
      "startTime": "08:00:00",
      "endTime": "18:00:00",
      "repeatRule": "daily",
      "status": "pending"
    }
  ]
}
```

## 2. 新建

**POST** `/v1/child/exercise-reminders`

### Body（JSON）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| elderProfileId | number | 是 | |
| title | string | 是* | *若空，前端会先按锻炼类型生成默认标题再提交 |
| exerciseType | string | 是 | 自由文本 |
| startTime | string | 是 | `HH:mm:ss` |
| endTime | string | 是 | `HH:mm:ss` |
| remindTime | string | 是 | UTC ISO8601，如 `2026-05-03T04:58:19.510Z` |
| repeatRule | string | 是 | `none` / `daily` / `weekly` |
| enabled | boolean | 是 | 当前固定 `true` |
| sourceType | string | 是 | 固定 `child_remote` |
| status | string | 是 | 固定 `pending` |
| createdBy | string | 是 | 固定 `child` |

前端**不传**：`goalValue`、`goalUnit`、`intervalMinutes`。若库表这些列非空且无默认值，由服务端在入库时补齐。

### 成功条件

- HTTP 2xx，且响应体为 JSON（空响应体会导致前端报错）。
- `code == 0`。

`data` 可为任意类型；建议返回新建记录或至少包含 `id`，便于联调。

---

## 3. 修改

**PUT** `/v1/child/exercise-reminders/{id}`

`id`：提醒主键。

### Body（JSON）

| 字段 | 类型 | 必填 |
|------|------|------|
| title | string | 是（逻辑上可由服务端在空时按 exerciseType 默认） |
| exerciseType | string | 是 |
| repeatRule | string | 是 |
| startTime | string | 是，`HH:mm:ss` |
| endTime | string | 是，`HH:mm:ss` |

### 成功条件

- HTTP 2xx。
- 若响应体非空：须为 JSON 且 `code == 0`。响应体为空时前端不校验 `ApiResponse`。

---

## 4. 删除

**DELETE** `/v1/child/exercise-reminders/{id}`

`id`：提醒主键。

### 成功条件

HTTP 2xx；前端不解析响应体，成功后会再次请求列表刷新。

---

## 与表 `exercise_reminders` 的提示

- `exercise_type` 对应前端 `exerciseType`；注意与 `VARCHAR(50)` 等约束一致。
- `source_type`、`created_by`、`status`、`remind_time`、`repeat_rule`、`enabled` 等与 POST 约定一致或由业务扩展。
- `goal_value`、`goal_unit`、`interval_minutes` 若库表必填：仅在服务端给默认值即可。

---

## 路径前缀说明

若全局 API 挂在例如 `/api` 下，应在网关或 `AppConfig.apiBase` 中统一配置；**相对路径仍以本文 `/v1/child/exercise-reminders` 为准**。
