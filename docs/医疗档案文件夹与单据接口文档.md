# 医疗档案 · 文件夹与单据接口文档

本文档与 Flutter 客户端 `mobile/lib/features/medical_hub/data/medical_hub_api.dart` 对齐，供后端联调与验收。

**对应页面：**

- 医疗档案列表 / 文件夹 / 归档：`MedicalArchivePage`
- 单据详情 / 编辑 / 结构化展示：`MedicalDocumentDetailPage`
- 拍照识别：`MedicalSmartHubPage`

---

## 1. 通用约定

| 项 | 说明 |
|----|------|
| Base URL | 与 `AppConfig.apiBase` 一致（含 `/api` 上下文） |
| 鉴权 | `Authorization: Bearer <token>` |
| JSON 请求 | `Content-Type: application/json` |
| 上传识别 | `Content-Type: multipart/form-data` |
| 统一响应 | `{ "code": 0, "message": "ok", "data": ... }`，**`code == 0` 为成功** |
| 字段命名 | **camelCase 优先**；前端兼容 snake_case（如 `elder_profile_id`、`folder_id`） |
| 子女端 | 操作某老人数据时，Query 或 Body 带 **`elderProfileId`**（与绑定老人 ID 一致） |

失败示例：

```json
{
  "code": 40001,
  "message": "无权限访问该老人档案",
  "data": null
}
```

## 2. 接口一览

| 方法 | 路径 | 说明 | 前端状态 |
|------|------|------|----------|
| POST | `/v1/medical/smart-recognize` | 拍照识别并归档 | 已有，响应字段扩展 |
| GET | `/v1/medical/folders` | 病情文件夹列表 | **已对接** |
| POST | `/v1/medical/folders` | 新建病情文件夹 | **已对接（新建）** |
| GET | `/v1/medical/documents` | 医疗档案列表 | 已有，列表项扩展 |
| GET | `/v1/medical/documents/{id}` | 单据详情 | 已有，响应字段扩展 |
| GET | `/v1/medical/documents/{id}/file` | 单据原件图片 | 已有 |
| PATCH | `/v1/medical/documents/{id}` | 编辑 / 归档至文件夹 | **已对接（扩展）** |
| DELETE | `/v1/medical/documents/{id}` | 删除档案 | **已对接（新建）** |

> 说明：**新建**指前端新调用的 HTTP 方法或路径；**扩展**指同一路径增加请求/响应字段。

## 3. 病情文件夹

### 3.1 列表文件夹

**GET** `/v1/medical/folders`

**Query**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| elderProfileId | long | 子女端必填 | 老人档案 ID |

**成功 `data`：** JSON 数组

| 字段 | 类型 | 说明 |
|------|------|------|
| id | long | 文件夹 ID |
| elderProfileId | long | 所属老人 |
| name | string | 文件夹名称 |
| sortOrder | int | 排序，越小越靠前 |

**响应示例：**

```json
{
  "code": 0,
  "message": "ok",
  "data": [
    {
      "id": 12,
      "elderProfileId": 3,
      "name": "幽门螺旋杆菌",
      "sortOrder": 0
    }
  ]
}
```

---

### 3.2 新建文件夹

**POST** `/v1/medical/folders`

**Request Body**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| elderProfileId | long | 是 | 老人档案 ID |
| name | string | 是 | 文件夹名称，非空 |

**请求示例：**

```json
{
  "elderProfileId": 3,
  "name": "幽门螺旋杆菌"
}
```

**成功 `data`：** 新建文件夹对象（字段同 3.1 列表项）

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 13,
    "elderProfileId": 3,
    "name": "2026年检查",
    "sortOrder": 1
  }
}
```

**建议后端约束：**

- 同一 `elderProfileId` 下 `name` 可不重复（重复时 `code != 0`）
- 表：`medical_archive_folders`（或项目等价表）

## 4. 医疗档案（单据）

### 4.1 列表档案

**GET** `/v1/medical/documents`

**Query**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| elderProfileId | long | 子女端必填 | 老人档案 ID |
| folderId | long | 否 | 传入时仅返回该文件夹内单据 |
| docCategory | string | 否 | `LAB_REPORT` / `PRESCRIPTION` / `BILLING` / `RECORD` / `OTHER` |

**成功 `data`：** JSON 数组

| 字段 | 类型 | 说明 |
|------|------|------|
| id | long | 单据 ID |
| elderProfileId | long | |
| title | string | 列表标题 |
| docCategory | string | 类别 |
| routedSpecializedApi | string | 结构化路由标识 |
| createdAt | string | ISO-8601 |
| folderId | long / null | **扩展**：所在文件夹；`null` 表示未归档 |
| folderName | string | **扩展**：文件夹名称（可选，便于展示） |

**响应示例：**

```json
{
  "code": 0,
  "message": "ok",
  "data": [
    {
      "id": 5,
      "elderProfileId": 3,
      "title": "幽门螺旋杆菌测验",
      "docCategory": "LAB_REPORT",
      "routedSpecializedApi": "medical_report_detection",
      "createdAt": "2026-05-17T15:42:00",
      "folderId": 12,
      "folderName": "幽门螺旋杆菌"
    }
  ]
}
```

---

### 4.2 单据详情

**GET** `/v1/medical/documents/{id}`

**Query：** `elderProfileId`（子女端建议携带）

**成功 `data` 字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | long | |
| elderProfileId | long | |
| title | string | |
| docCategory | string | |
| fullText | string | OCR 原文 |
| routedSpecializedApi | string | |
| structuredRouteSource | string | `keyword_text` / `doc_classify` 等 |
| structuredError | string | 结构化失败原因；空表示无错误 |
| createdAt | string | |
| folderId | long / null | 归档文件夹 |
| folderName | string | 可选 |
| extractedFields | object | 抽取字段（类别、日期、关键词等） |
| displayBlocks | array | **优先渲染**，有序展示块 |
| structuredFields | object | 中文键 → 字符串值 |
| ocr | object | 完整 OCR 结果 |

**`displayBlocks` 元素：**

| type | 字段 | 说明 |
|------|------|------|
| `title` | text | 标题行（医院名等） |
| `kv` | label, value | 字段名与值 |
| `note` | text | 备注 |
| `paragraph` | text | 段落 |

**示例：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 5,
    "title": "幽门螺旋杆菌测验",
    "docCategory": "LAB_REPORT",
    "fullText": "北京大学人民医院\n检验项目\n碳13尿素呼气试验\n……",
    "displayBlocks": [
      { "type": "title", "text": "北京大学人民医院" },
      { "type": "kv", "label": "检验项目", "value": "碳13尿素呼气试验" },
      { "type": "kv", "label": "样本类型", "value": "呼气" }
    ],
    "structuredFields": {
      "检验项目": "碳13尿素呼气试验",
      "样本类型": "呼气"
    },
    "structuredError": null,
    "extractedFields": {
      "docCategory": "LAB_REPORT",
      "normalizedDates": ["2026-05-17"],
      "matchedKeywords": ["检验"]
    },
    "ocr": {
      "fullText": "……",
      "routedSpecializedApi": "medical_report_detection",
      "specializedRaw": { }
    }
  }
}
```

**前端展示优先级：**

1. `displayBlocks` → 按序渲染  
2. 无则 `structuredFields` → 键值表  
3. 无则 `fullText` 纯文本  
4. `fullText` 在有结构化数据时放入折叠「查看 OCR 原始全文」

### 4.3 单据原件

**GET** `/v1/medical/documents/{id}/file`

**Query：** `elderProfileId`（可选）

**响应：** 图片二进制流（`image/jpeg` 等）

---

### 4.4 编辑单据 / 归档至文件夹（扩展 PATCH）

**PATCH** `/v1/medical/documents/{id}`

**Query：** `elderProfileId`（子女端建议携带）

**Request Body（至少一项，均为可选组合）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| title | string | 修改标题 |
| fullText | string | 修改 OCR 全文；**后端应重新生成** `displayBlocks`、`structuredFields`、`extractedFields` |
| docCategory | string | 修改类别 |
| folderId | long / null | **归档**：目标文件夹 ID；**`null` 表示移出文件夹** |

**编辑全文示例：**

```json
{
  "title": "门诊检验申请单",
  "fullText": "检验项目：碳13尿素呼气试验\n样本类型：呼气",
  "docCategory": "LAB_REPORT"
}
```

**移入文件夹示例：**

```json
{
  "folderId": 12
}
```

**移出文件夹示例：**

```json
{
  "folderId": null
}
```

**成功 `data`：** 建议返回更新后的完整单据对象（含 `displayBlocks`、`folderId` 等），便于前端刷新详情/列表。

---

### 4.5 删除档案（新建 DELETE）

**DELETE** `/v1/medical/documents/{id}`

**Query：** `elderProfileId`（子女端建议携带）

**成功：**

```json
{
  "code": 0,
  "message": "ok",
  "data": null
}
```

**建议：**

- 软删除或硬删除需与产品一致
- 同步处理原件文件存储
- 关联日历事件 `sourceDocumentId` 的处理策略需在 `message` 或文档中说明

## 5. 智能识别（响应扩展）

**POST** `/v1/medical/smart-recognize`

**Form Data**

| 字段 | 说明 |
|------|------|
| file | 图片文件 |
| elderProfileId | 可选，子女端归档对象 |

**成功 `data` 建议包含（在原有基础上）：**

| 字段 | 说明 |
|------|------|
| documentId | 归档后的单据 ID |
| ocr | OCR 结果对象 |
| extractedFields | 抽取字段 |
| suggestedCalendarEvents | 日历建议 |
| displayBlocks | 与详情一致，识别完成即入库 |
| structuredFields | 扁平结构化字段 |
| structuredError | 结构化失败原因（可空） |

识别完成后，**GET 详情** 应能读到与识别响应一致的 `displayBlocks` / `structuredFields`。

## 6. 前端调用对照

| 用户操作 | 接口 |
|----------|------|
| 打开医疗档案 | `GET /folders` + `GET /documents` |
| 新建文件夹 | `POST /folders` |
| 点击文件夹筛选 | `GET /documents?folderId=`（或客户端本地筛选） |
| 归档 / 移出文件夹 | `PATCH /documents/{id}`，`folderId` 为目标 ID 或 `null` |
| 删除档案 | `DELETE /documents/{id}` |
| 查看详情 | `GET /documents/{id}` + `GET /documents/{id}/file` |
| 编辑全文保存 | `PATCH /documents/{id}` → 再 `GET` 详情刷新结构化字段 |
| 拍照识别 | `POST /smart-recognize` |
