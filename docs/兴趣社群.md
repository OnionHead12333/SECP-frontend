## 1. 通用约定

### 1.1 鉴权

除明确标注「公开」外，请求头需携带：

```http
Authorization: Bearer <JWT>
```

- JWT 算法 HS256，登录成功后返回，默认有效期 **7 天**
- 解析出 `userId`、`role`（`elder` | `child`）
- **dev 环境**：`POST /v1/dev/token` 可签发测试 token；亦支持演示 token（见 Security 配置）

### 1.2 统一响应 `ApiResponse<T>`

```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```

| code | 含义 |
|------|------|
| `0` | 成功 |
| `4000` | 参数校验失败 |
| `401` / `4011` | 未登录 / token 过期 |
| `403` | 无权限（角色或家庭绑定不符） |
| `404` | 资源不存在 |
| `409` | 冲突（如重复添加好友、重复手机号） |

- 部分业务错误仍返回 HTTP 200，以 `code != 0` 判断
- 文件下载接口（如医疗原图）返回 **二进制流**，不走 JSON 信封

### 1.3 身份与档案

| 概念 | 字段 | 说明 |
|------|------|------|
| 用户 | `users.id` | 登录账号，含 `role` |
| 老人档案 | `elder_profiles.id` | 业务主键；子女端路径常用 `{elderProfileId}` |
| 家庭绑定 | `family_bindings` | 子女访问老人数据须 `status = active` |

**兴趣社群 scopeKey**（与前端 `CommunityScope` 对齐，写入消息/好友表）：

1. 优先 `phone_{11位手机号}`（如 `phone_13800138001`）
2. 否则 `elder_{elderProfileId}`
3. 演示群友固定 `demo_peer_wang` 等（见 `community_demo_peer_profiles`）

### 1.4 时间格式

- 请求/响应推荐 **ISO 8601**：`2026-04-11T10:30:05` 或带毫秒 `2026-04-11T10:30:05.123`
- 日期字段：`yyyy-MM-dd`

## 3. 老人资料（已实现）

**前缀：** `/v1/elder/profile`  
**角色：** `elder`

### GET `/v1/elder/profile`

**响应 `data`**

| 字段 | 说明 |
|------|------|
| `name` | 称呼/姓名 |
| `phone` | 手机号 |
| `gender` | `male` \| `female` \| `unknown` |

**请求体（均可选，至少一项）**

```json
{
  "name": "张建国",
  "gender": "male",
  "birthday": "1950-05-15"
}
```

### POST `/v1/elder/profile/avatar` — **V13 规划**

从相册上传头像（对应前端 `ElderAvatarPickerTile`）。

- **Content-Type：** `multipart/form-data`
- **字段：** `file`（jpg/png，建议 ≤ 2MB）
- **行为：** 存储至对象存储/本地目录，更新 `users.avatar_url`
- **响应 `data`：** `{ "avatarUrl": "/uploads/avatars/phone_13800138001.jpg" }`

### 11.2 老人端接口

> **后端实现用完整 OpenAPI 说明：** 见 [`兴趣社群-老人端群聊-OpenAPI.md`](./兴趣社群-老人端群聊-OpenAPI.md)（含 schemas、请求/响应示例、软清空表结构、YAML 片段）。

**前缀：** `/v1/elder/interest-communities`  
**角色：** `elder`

#### GET `/` — 社群目录 + 是否已加入

**响应 `data`：** `InterestCommunityBrief[]`（4 个固定群，来自 `interest_communities`）

#### GET `/memberships` — 已加入群 ID

**响应 `data`**

```json
{
  "joinedCommunityIds": ["taiji", "calligraphy"],
  "scopeKey": "phone_13800138001"
}
```

#### POST `/memberships` — 加入社群

**请求体**

```json
{ "communityId": "taiji" }
```

**服务端行为**

1. 写入 `interest_community_memberships`（`status=active`）
2. 若该群尚无消息，插入欢迎语（`sender_scope_key=system`）
3. 若 `community_peer_seed_log` 无记录，播种演示群友消息（王阿姨、李叔叔）并写 log

**响应 `data`：** 更新后的 membership 摘要

#### DELETE `/memberships/{communityId}` — 退出社群

- 更新 `status=left`，**不删除**历史群消息（与前端演示一致）

#### GET `/{communityId}/messages` — 群聊消息（分页）

**查询参数**

| 参数 | 说明 |
|------|------|
| `before` | 可选，消息 ID，向上翻页 |
| `limit` | 默认 50，最大 200 |

**响应 `data`**

```json
{
  "items": [ /* CommunityMessage[]，按 createdAt 升序 */ ],
  "hasMore": false
}
```

#### POST `/{communityId}/messages` — 发送消息

**文字消息 — JSON**

```json
{
  "kind": "text",
  "textContent": "大家好"
}
```

**语音消息 — multipart**

- `kind=voice`
- `file`：m4a/aac，最短 **400ms**，否则 `400`
- 服务端存盘并写 `audio_url`、`duration_ms`

**响应 `data`：** 完整 `CommunityMessage`

#### DELETE `/{communityId}/messages` — 清空群聊（当前用户视角）

- **不删除** `interest_community_messages` 行及语音/图片文件
- 为当前查看者写入或更新 `clear_before_millis`（按 `scopeKey` + `communityId`）
- 之后 GET 消息仅返回 `createdAtMillis > clear_before_millis` 的记录
- 老人清空不影响子女预览；子女清空不影响老人与其他群友

### 11.3 老人好友

**前缀：** `/v1/elder/friends`  
**角色：** `elder`

#### GET `/` — 好友列表

按 `added_at` **降序**。

#### GET `/discover` — 可添加候选

**查询参数：** `phone`（可选，11 位手机号精确匹配）

**响应 `data`：** `ElderFriendCandidate[]`

- 命中 `community_demo_peer_profiles` 或已注册老人（按手机号）
- 不含自己

#### POST `/` — 添加好友

**请求体**

```json
{
  "phone": "13800001101"
}
```

或直接指定演示账号：

```json
{
  "scopeKey": "demo_peer_wang"
}
```

**规则**

- 单向通讯录，无需对方确认
- 去重：`owner + phone` 或 `owner + friend_scope_key` 冲突 → `409`
- 未知手机号：`scopeKey=phone_{phone}`，`displayName=手机尾号xxxx`

#### DELETE `/{friendScopeKey}` — 删除好友

- 无通知（与前端演示一致）

### 11.4 老人私聊

**前缀：** `/v1/elder/direct-messages`  
**角色：** `elder`

#### GET `/threads/{peerScopeKey}/messages`

**路径参数：** `peerScopeKey` — 对方 scope（如 `demo_peer_wang`）

**查询参数：** 同群聊分页

**服务端：** 按字典序构造线程键 `min(scopeA,scopeB)__max(...)`，映射 `direct_message_threads`

#### POST `/threads/{peerScopeKey}/messages`

- 支持 JSON 文字或 multipart 语音（规则同群聊）
- 仅老人可发（`sender_role=elder`）

### 11.5 子女端预览

**前缀：** `/v1/child/elders/{elderProfileId}/interest-communities`  
**角色：** `child`，须 **active 家庭绑定**

#### GET `/` — 父母兴趣社群总览

**响应 `data`**

```json
{
  "elderProfileId": 1,
  "elderDisplayName": "张建国",
  "communities": [
    {
      "community": { /* InterestCommunityBrief */ },
      "joined": true,
      "latestMessage": { /* CommunityMessage | null */ }
    }
  ]
}
```

- 列表按 `latestMessage.createdAt` **降序**
- 仅返回老人 **已加入** 的群

#### GET `/{communityId}/messages` — 只读群聊

- 与老人端 GET 消息相同，但 **`mine` 按绑定老人 scope 计算**（父母消息在右侧）
- **禁止** POST 发消息

#### DELETE `/{communityId}/messages` — 清空群聊（子女端）

- 与老人端相同：仅对**当前子女账号 + 绑定老人**的预览视角写入 `clear_before_millis`
- 不删除群共享消息数据

## 14. V13 实施建议（后端）

1. **优先链路：** 目录 → 入群 → 群消息列表/发送 → 好友 CRUD → 私聊 → 子女只读预览
2. **鉴权复用：** `SecurityUtils.requireRole` + `FamilyBindingService.assertActiveBinding`
3. **scopeKey 工具类：** 与前端 `CommunityScope.forCurrentElder()` 规则一致
4. **语音存储：** 参考医疗模块 `MedicalDocument` 本地/OSS 策略
5. **消息上限：** 单群/单线程保留最近 200 条（与前端演示一致，可配置）
